AWS Sessions for GSB 5544

Computing and Machine Learning for Business Analytics

This site holds the AWS-focused sessions being developed for GSB 5544. It exists so collaborators can see, in one place, what has been built so far and what students will actually do in each session. Every document is rendered here as a web page and is also available as a downloadable notebook or as a one-click Google Colab link.

NoteHow students reach AWS

Session 1 assumes each student has a free AWS account on the AWS Free Plan: $100 of credits for six months, and the account pauses rather than bills when they run out. The pre-class reading walks students through creating the account, the one-time SageMaker Studio setup, and starting and stopping the JupyterLab space. Courses that provide the AWS Academy Learner Lab (aws.amazon.com/training/awsacademy) instead can follow the same steps; the reading notes the three differences. Data comes from the public noaa-ghcn-pds bucket on the Registry of Open Data on AWS. Compute is a SageMaker Studio JupyterLab space on an ml.t3.medium and Athena queries, both in us-east-1. A full session costs a student roughly 20 to 30 cents if they stop the space when they finish, and stopping it is graded.

What Session 1 teaches about AWS: space, ability, and cost

The module is organized around three questions an analyst asks of any cloud, and it answers each one with numbers the students produce themselves.

  • Space. Storage is separate from compute and has no practical ceiling. Students read the size of a 1.3 GB file without downloading it, total a decade of files against their own RAM, and learn what S3 storage, requests, and data transfer cost per gigabyte. They see that transfer inside a region is free and transfer to a laptop is not, which is why the notebook runs next to the bucket.
  • Ability. Compute is rented by the hour in sizes you choose. Students run the same psutil cell on their laptop and inside a rented ml.t3.medium, put the two side by side, and see an instance-type table from 2 cores and 4 GB at $0.05 per hour up to 96 cores and 384 GB at about $5.50 per hour. They then hand a WHERE clause to Athena’s fleet and watch it scan a fraction of the file in seconds.
  • Cost. Every code cell says where it runs. The reading has a section on what the instance costs per hour, what Athena charges per terabyte scanned, and the difference between a notebook that is open and a space that is running, with worked examples (a class session: 15 cents; a forgotten month: $36). The practice activity ends with a graded cost audit and a verified teardown.

How a session is structured

Each session follows the same three-part pattern, so students always know what to expect.

  1. Pre-class reading (01_*.md). A self-contained explainer with runnable code snippets. Students read it and run the code on their laptop before class, write down their machine’s numbers and one timing, and start the Learner Lab once so the SageMaker domain exists. It ends with a short reading check.
  2. Topics of practice (02_*.ipynb). An in-class, fill-in-the-blank walkthrough of every function introduced in the reading, run inside SageMaker Studio. Blanks are marked ____. The instructor version has the blanks filled in.
  3. Practice activity (03_*.ipynb). A business scenario with numbered questions and empty code cells, also run inside SageMaker Studio. Students work through it in class or as homework. The solutions version has every cell completed.

Every code cell in both notebooks begins with one of three lines: # RUNS ON: laptop, # RUNS ON: SageMaker ml.t3.medium (us-east-1), or # RUNS ON: Athena fleet (results land in S3). The build script refuses to generate a notebook where any cell lacks one.

The two notebooks are generated from a single source file, build_notebooks.py, so the student and solutions versions never drift apart. Editing the source and re-running the script regenerates all four notebooks.

Session 1 · Data Bigger Than Your Laptop

What students will learn

By the end of Session 1, students can:

  • Measure how much RAM a machine actually has available, and explain why “total” is not “available” and why disk is not memory.
  • Read and reason in the units of data (KB through PB) and estimate whether a file will fit in pandas before trying to load it.
  • Use the core AWS vocabulary: region, S3, bucket, object, key, prefix, EC2, instance type, Athena, IAM, and anonymous (unsigned) access.
  • Explain where a notebook’s code runs (kernel, instance, region co-location) and open a SageMaker Studio JupyterLab space in the Learner Lab.
  • Connect to a public S3 bucket without an account, list objects, read an object’s size from metadata alone, and peek at a file with a byte-range request.
  • Extract a single station’s full history rather than a whole year of global data, filter it at the source, transform it, and plot it, on a rented machine in the same region as the data.
  • Run a SQL WHERE clause on Athena’s fleet against Parquet files in S3, read the bytes-scanned statistic, and compare it to reading the CSV.
  • Estimate what a session cost, empty their results bucket, stop the space, and prove it.

Dataset

All exercises use the NOAA GHCN-Daily dataset in the public noaa-ghcn-pds bucket. The by-year CSV files are multi-gigabyte and will not fit on a laptop or on the rented instance, which is the point. The by-station files are small enough to pull and analyze. The same data also exists as Parquet partitioned by YEAR= and ELEMENT=, which is what Athena reads.

What students will do, in order

Before class: the pre-class reading. Students work through seven sections on their laptop, write down five machine numbers and one timing, start the Learner Lab once, and answer a six-question reading check:

  1. What your machine actually has
  2. The units of data
  3. The vocabulary of AWS
  4. Where does the code run? (kernel, instance, co-location, opening a SageMaker Studio space)
  5. Reading from S3 without an account
  6. Extraction strategy: filter at the source, plus the fourth lever (Athena)
  7. Cost, space, and ability: what you are actually renting

In class: the topics-of-practice notebook, run inside SageMaker Studio. A guided, fill-in-the-blank tour, one block at a time:

  • A. Two machines, side by side (laptop numbers versus the rented instance)
  • B. The units of data
  • C. The vocabulary of AWS
  • D. Connect without an account
  • E. Read a size without reading the file
  • F. Peek at a file with a range request
  • G. Extract one station, not one year
  • H. Transform
  • I. Bring the visual
  • J. Ask Athena for the same station (results bucket, table over the Parquet files, query, bytes scanned)
  • K. Stop the meter (empty the bucket, stop the space, end the lab)

In class or as homework: the practice activity, run inside SageMaker Studio. Students play an inventory planner for a beverage distributor with two markets, San Luis Obispo and Phoenix, and need each market’s weather history before anyone builds a demand model. Thirteen questions across five sets:

  • Set 1 · Capacity. Report both machines in one table, estimate how many rows fit, and total a decade of by-year files against available RAM.
  • Set 2 · Vocabulary in action. List prefixes, explain why a “folder” is not a folder, and read file metadata without downloading.
  • Set 3 · Extraction. Write a reusable load_station() function, pull both markets, count hot days per year, and compute monthly rainfall.
  • Set 4 · Visualize and interpret. Chart both markets and write the business read, including which compute tier the planner would choose for a weekly refresh.
  • Set 5 · Where the work runs. Time the same extraction three ways (laptop, SageMaker, Athena), compute hot days straight from the fleet and compare bytes scanned, then a graded cost audit and teardown with evidence that the space is stopped.

What students need

  • On their laptop, for the pre-class reading:
pip install psutil boto3 s3fs pandas matplotlib
  • A free AWS account, created before class by following section 4 of the pre-class reading, with SageMaker Studio set up once. Inside SageMaker Studio the default image already has every library; the setup cell installs s3fs in case it is missing.
